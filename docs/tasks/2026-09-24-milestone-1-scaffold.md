# Milestone 1 — scaffold & repository management

- **Date:** 2026-09-24
- **Branch:** `feat/m1-scaffold`
- **Status:** done (awaiting review; not committed)

## Context

Greenfield Electron Git client modeled on JetBrains Git tooling. Milestone 1 covers the project
scaffold, security model, typed IPC, `GitService` with git detection and the command console,
packaging config, and all repository management: welcome screen, recents (search, pin, groups,
missing repos), open / drag-and-drop / init / clone / scan, tabs, repo switcher, quick switcher,
session restore, single instance and command-line opening.

## Decisions

- **Versions pinned for compatibility, not "latest everything".** electron-vite 5 supports Vite ≤ 7,
  and typescript-eslint supports TypeScript < 6.1, so: Electron 44, electron-vite 5, Vite 7,
  `@vitejs/plugin-react` 5, TypeScript 5.9, React 19 (spec says 18+), Tailwind 4, Vitest 5.
- **All runtime JS is bundled; `dependencies` is empty.** electron-vite externalizes only
  `dependencies`, so ESM-only packages (electron-store 11, chokidar 5) in `devDependencies` are
  bundled into the CJS main bundle. Keeps the asar tiny and avoids ESM/CJS interop in main.
- **`"type": "commonjs"`** so the preload is emitted as CJS — sandboxed preloads cannot be ESM.
- **IPC envelope.** Every handler returns `IpcResult<T>`; the renderer's `api` facade unwraps and
  throws `ApiError` carrying git's stderr and the command. Plain `ipcMain.handle` throws lose that data.
- **Channel allowlists derived with `satisfies Record<Channel, true>`**, so adding a channel to the
  type map without allowlisting it (or vice versa) is a compile error. Main also validates the sender
  frame URL.
- **Renderer-chosen operation ids** for clone/scan, so the renderer can cancel while `invoke()` is
  still pending (no separate "start"/"await" channels).
- **`GIT_TERMINAL_PROMPT=0`** on every command: a missing credential fails fast instead of hanging
  on an invisible prompt. Credential helpers and ssh-agent still work.
- **Global `-c core.quotepath=false -c color.ui=false`** (+ `core.longpaths=true` on Windows) on
  every invocation; the console shows the caller's args without this prefix.
- **git detection:** configured path (no silent fallback, so a wrong setting is visible) → `PATH` →
  common install dirs. Only real executables (`git.exe`), never `.cmd` wrappers that need a shell.
- **Recents model is pure** (`recentsModel.ts`) and unit-tested; `RecentsService` applies it to the
  store. The 50-entry cap only applies to unpinned, ungrouped entries (curated entries are kept).
- **Path identity:** `realpath.native` + trailing-separator strip; comparison key lower-cased on
  Windows. Prevents duplicate recents via symlinks or case differences.
- **Shortcuts are handled in the renderer** (with `preventDefault()`, which stops Electron firing the
  menu accelerator too). The menu still lists them. Reason: synthetic key events (Playwright) never
  reach native accelerators, and editors in later milestones need to claim keys first.
- **Session is saved immediately on tab open/close/switch**, debounced only for per-tab UI state,
  and flushed on unload.
- **Open semantics:** Welcome click → open (or focus) as a tab; Ctrl/middle click → background tab.
  Repo switcher click → replace current tab; Ctrl+click → new tab. Quick switcher Enter → tab.
- **Theme:** CSS variables under `prefers-color-scheme`; main sets `nativeTheme.themeSource` from
  settings, so no class toggling in the renderer.
- **CSP** is injected by a small Vite plugin: strict in builds, relaxed (inline scripts for React
  refresh, ws for HMR) only in dev.
- **Icon** generated by `scripts/generate-icon.mjs` (pure Node PNG encoder), because no image tools are
  assumed on build machines.

## Rejected alternatives

- **Custom frameless title bar** with the switcher inside the OS title bar: cross-platform window
  controls and Wayland drag regions are a large surface; used an app header row instead.
- **Keeping all tab views mounted** to preserve DOM state: will not scale once each tab hosts a 100k-row
  log. Per-tab state lives in the tabs store (`ui` record, persisted) instead.
- **Distinguishing interactive vs plain rebase** via `rebase-merge/interactive`: modern git writes that
  file for plain rebases too (merge backend runs through the sequencer). Only `rebase` is reported.
- **electron-store `clearInvalidConfig: true`:** would silently wipe user data on a schema mismatch.
  The file is moved aside instead.

New project. Main pieces:

## Evidence

- `npm run typecheck` — clean. `npm run lint` — clean.
- `npm test` — 10 files, 61 tests pass (unit: fuzzy, display, parsers, recents model, CLI, git
  detection, command tokenizer, shortcuts; integration on temp repos: resolve (subdir, file, `.git`,
  bare, spaces/unicode), init, info (detached, worktree, submodule, merge/rebase in progress),
  quickStatus (ahead/behind vs a bare remote, dirty), clone with progress, clone cancellation,
  URL-as-option refusal, no-shell verbatim args, console logging, CRLF bytes preserved).
- `npm run test:e2e` — 3 Playwright tests pass, three consecutive runs: CLI path opens a tab and
  renderer security prefs are `sandbox/contextIsolation on, nodeIntegration off`, `require`/`process`
  undefined in the page; session restore + Recents + type-to-search + Enter; Git Console via `Alt+9`.
- `npm run dist:linux` — produced AppImage, `.deb` (Depends includes `git`; postinst installs
  `/usr/bin/gitclient` via update-alternatives and an AppArmor profile on Ubuntu 24+), `.tar.gz`.
- Packaged binary: `gitclient .` in repo A, then `gitclient B` from another shell → second process
  exits 0, running window gets B as a new tab (verified via persisted session).

## Corrections

- First e2e failures looked like a race in opening tabs. Actual causes: (1) a Zustand selector
  returning a fresh array (`Object.values`) caused an infinite render loop (React #185);
  (2) Playwright key presses do not trigger native menu accelerators; (3) the 300 ms session-save
  debounce lost the session when quitting right after opening a repo. All three fixed at the source.
- Launching `electron out/main/index.js` directly reports Electron's version as `app.getVersion()`
  (no package.json next to the entry). E2E now launches the project directory.

## Deliberately not done

- Log, branches, commit, etc. (milestones 2+). `RepoView` is a placeholder with repo facts.
- Windows is not exercised here (no Windows machine in this session); CI matrix comes in milestone 10.
  Windows-specific code paths: `.exe`-only git detection, `taskkill /T` cancellation, long paths,
  `.cmd` editor launchers via `cmd /d /s /c` with a metacharacter refusal.
- NSIS "add to PATH", Explorer context menu, jump list, Nautilus script: milestone 9/10.
- Git Console is not virtualized (shows the last 1000 of 2000 kept entries).
- The watcher covers `.git` metadata only (HEAD, refs, index, in-progress markers), not the working
  tree — that comes with Local Changes (milestone 6).
- Folder scan does not descend into found repositories (nested repos/submodules are not listed).
- Bare repositories are refused with a message.
- `repo:watch` re-runs `git info` (4 cheap commands) to find the git dirs; could reuse cached info.

## How to verify

```bash
npm install
npm run typecheck && npm run lint && npm test
npm run test:e2e
npm run dev
```

In the app: welcome screen lists nothing on first run → Open Folder… a repo subfolder opens the repo
root as a tab; open a non-repo folder → "Initialize a Git repository here?"; Clone… with a URL shows
live progress and can be cancelled; Scan Folder… finds repos and adds them (optionally to a group);
right-click entries for pin/rename/group/remove; `Ctrl+E` quick switcher; `Alt+9` console; restart →
tabs restored.
