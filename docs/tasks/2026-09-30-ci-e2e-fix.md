# Fix failing Linux e2e job in CI

- **Date:** 2026-09-30
- **Branch:** `fix/ci-e2e`
- **Status:** done

## Context

The Linux CI job has failed on every push since `1c4dddd` (2026-09-24); only
the "End-to-end tests" step fails, typecheck/lint/unit tests and the Windows
job pass. Latest run (`a016f65`) had 4 failures; earlier runs showed a
slightly different set, which pointed at two classes of problem:
environment-dependent failures and races.

| Spec | Symptom in CI | Root cause |
| --- | --- | --- |
| `rewrite.spec.ts` (reword) | reworded row never appears | runner has no global git identity; the app's own `git rebase -i` cannot create commits ("Committer identity unknown"). Fails every run since the spec was added. |
| `worktree-conflicts.spec.ts` | `data-pending` never `true` | same: the app's `git merge` needs an identity. |
| `window-state.spec.ts` | `isMaximized()` stays `false` | `xvfb-run` starts a bare X server with no window manager; `BrowserWindow.maximize()` is an EWMH request nobody handles. |
| `branches.spec.ts` (bulk delete) | `unmerged` still listed | race: the test waited on `merged-1` disappearing, which already happens before the force-delete prompt, then read `git branch` before the forced delete ran. |
| `conflicts.spec.ts` (rebase, older run) | `Fix login` missing from log | race: the operation banner can vanish during a refresh before `rebase --continue` finishes; git log read too early. |

## Decisions

- Test repos in `rewrite`/`worktree-conflicts` get a repo-local
  `user.name`/`user.email`, the same pattern `commit.spec.ts` and
  `conflicts.spec.ts` already use. Keeps specs hermetic (also for contributors
  without a global identity) instead of depending on runner config.
- CI installs `openbox` and runs the suite as
  `xvfb-run -a bash -c 'openbox & npm run test:e2e'`. openbox starts while
  electron-vite builds, long before the first window; it exits when Xvfb goes
  away, and the command's exit code is npm's.
- Git-state assertions after UI actions use `expect.poll` (and the branches
  test waits for the `unmerged` row, the one actually force-deleted).

## Rejected alternatives

- `git config --global user.*` in the workflow — fixes CI only; local runs
  without an identity would still fail.
- Skipping the maximize part of `window-state.spec.ts` on CI — loses the only
  coverage of the maximized-state persistence.
- Setting `GIT_AUTHOR_*`/`GIT_COMMITTER_*` in the `electron.launch` env —
  works, but diverges from the existing repo-config pattern.

## What changed

- `.github/workflows/ci.yml` — install openbox; run e2e under it.
- `e2e/rewrite.spec.ts`, `e2e/worktree-conflicts.spec.ts` — repo-local identity.
- `e2e/branches.spec.ts`, `e2e/conflicts.spec.ts` — wait for the real end state.

## Evidence

- Reproduced locally: with `GIT_CONFIG_GLOBAL` pointing at an empty file,
  `rewrite` and `worktree-conflicts` fail with the exact CI symptoms.
- Docker image replicating the runner (Ubuntu 24.04, Node 22, Xvfb, no git
  identity): `window-state` fails under plain `xvfb-run` exactly like CI.
- Same image, fixed branch, openbox: full `npm run test:e2e` → 20 passed;
  race-prone specs with `CI=true --repeat-each=3` → 27 passed.
- `npm run typecheck`, `npm run lint` clean.

None.

## Deliberately not done

- `window-state.spec.ts` also fails on a GNOME/Wayland desktop (unmaximize
  restores 1900×1137 instead of 1000×700) — a compositor behaviour difference,
  not the CI failure; not investigated.
- No CI run observed yet: the branch is not pushed (user pushes).

## How to verify

Push the branch and check the "Linux (typecheck, lint, tests, e2e)" job is
green. Locally, CI-like:

```bash
docker run --rm --user $(id -u):$(id -g) -e HOME=/tmp/h -e E2E_NO_SANDBOX=1 -v $PWD:/app -w /app <image with xvfb+openbox+node22> \
  bash -c "mkdir -p /tmp/h; xvfb-run -a bash -c 'openbox & npm run test:e2e'"
```
